# 墨印 · MoInk — 传输与驱动契约（CONTRACT）

> 本文档是**固件与页面之间的唯一权威接口定义**，以及**屏驱动的物理契约**。
> 改动任何一条必须同步更新 `check_frame.py` / `smoke_page.js` 并全量回归。
> 版本：version = R1.5.5（R1.2.0 起固件与控制页共用这一个号），api = 2。

## 1. 帧格式 v1 / v2（`POST /api/frame`）

整帧上传，**无局部刷新**。请求体 = 16 字节头（大端）+ 2bpp 载荷。

| 偏移 | 长度 | 字段 | 值 |
|---|---|---|---|
| 0–1 | 2 | 魔数 | `0xA5 0x5A` |
| 2 | 1 | 格式版本 | `1` = 768×552 载荷 / `2` = A1 原生 800×600 载荷（api 2 起） |
| 3 | 1 | 面板类型 | `0`=A0 / `1`=A1（**仅信息性**，实际面板由设备设置决定，不随帧切换） |
| 4–5 | 2 | 宽（大端） | `768`（v1）/ `800`（v2） |
| 6–7 | 2 | 高（大端） | `552`（v1）/ `600`（v2） |
| 8–11 | 4 | 载荷长度（大端） | `105984`（v1）/ `120000`（v2） |
| 12–13 | 2 | CRC16（大端） | CRC-16/CCITT-FALSE，仅对载荷字节计算 |
| 14–15 | 2 | 保留 | `0` |

- 载荷：`宽/4 × 高` 字节的 **2bpp** 位图——768×552 → `105984`；800×600 → `120000`。
- **几何接受规则**（`epd_frame_geom_ok()`，R1.5.4 收紧）：A0 只接受自身画像 768×552；
  **A1 的 768×552 两档都接受**（日历恒用 768×552）；**800×600 只在 `a1_mode=2`（对照档）被接受，
  且帧缓冲必须真有 120,000 字节** —— 缓冲按当前画像分配（R1.5.4 起默认档只有 105,984），
  收下超限帧等于把堆写穿。拒收时返回 `400`，页面上报几何与 `/api/info` 的生效 `a1_mode` 一致。
- CRC 算法：**CRC-16/CCITT-FALSE** — poly `0x1021`，init `0xFFFF`，无反射、无终异或（非 CCITT/IBM 反射变体）。黄金测试向量：`"123456789"` → `0x29B1`。
- 校验顺序：魔数 → 版本 → 宽高 → 载荷长度 → 流式收载荷并累加 CRC → CRC 比对。任一失败返回 `400`；缓冲被占用（上一帧正在刷）返回 `500 busy`。

## 2. 2bpp 位图编码

- 每字节 4 像素，**MSB 优先**：像素 `x` 位于字节内位 `(6 - 2*(x%4))`。
- 色码（A0 实测，与部分参考实现相反）：
  | 2bit 值 | 颜色 |
  |---|---|
  | `00` | 黑 K |
  | `01` | 白 W |
  | `10` | 黄 Y |
  | `11` | 红 R |
- 纯色整屏字节值：黑 `0x00`、白 `0x55`、黄 `0xAA`、红 `0xFF`。

## 3. 180° 几何契约（缓冲 ↔ 逻辑图）

缓冲与逻辑图像呈 **180° 旋转**关系（页面在浏览器里合成时已按此契约打包，固件只原样写屏）：

- 缓冲第 `r` 行 = 逻辑图像第 `y = H-1-r` 行（**自下而上**存储）。
- 每行内像素从左到右仍按 `x` 升序填充，但字节内 2bit 组序也倒（见 §2 的位映射）。
- 逻辑图 `(0,0)`（左上角）落在缓冲**最后一个字节的低 2 bit**。

页面的 `packIdx()` 与固件 `epd_display_2bpp()` 必须严格对应；`check_frame.py` 的 180° 放置断言即是此契约的黄金校验。

## 4. 屏画像：A0 / A1

### 4.1 玻璃与可见区（2026-09-23 真机定案，FB-013）

- 两种拆机屏（A0 批次、A1 批次）**可见区同为 768×552**，外观一致；
  帧里多出来的行列**不显示**（不会被"压进"画面）。
- **A1 栅极是顺序寻址的**（FB-013 真机否证了旧「两 bank 交错」模型）：
  用「原生 800×600」档顺序写栅极 0..599，得到的是**连续完整**的画面 ——
  无上下半屏穿插、无纵向条纹、无中部割裂，仅右 32 列 / 下 48 行被可见区裁掉。
  若栅极真为交错，顺序写入**必然**割裂；真机照片里完全没有该现象。
- **行内变换**：真机对照确认「勾选左右镜像才正向」 ⇒ A1 源线顺序与 A0 **同向**，
  行内**需要**整行镜像。FB-010 的"行内不作变换才正向"结论已被真机推翻。
- 结论：A1 的正解是**用 768×552 的帧、顺序写栅极**（1:1 落在栅极 0..551），
  而不是把 768×552 打散进偶 / 奇栅极。

### 4.2 A1 两档驱动模式（`a1_mode`，仅 A1 生效，默认 1）

| a1_mode | 名称 | 帧几何 | TRES / 刷新窗 | 写入窗 | 行 → 栅极 | 行内变换 |
|---|---|---|---|---|---|---|
| `1` | **768×552 顺序（默认·正解）** | 768×552 | 768×600 | `(0..767, 0..551)` | `y = i` | 固定整行镜像 |
| `2` | 方案A 原生 800×600（对照） | 800×600 | 768×600 | `(0..799, 0..599)` | `y = i` | 整行镜像（受「左右镜像」控制） |

- 两档走**同一条写入路径**：一个整窗 + 单次 `0x10` 连续发送全部行（每行 `w/4` 字节），
  整帧一个 CS 包络；`0x04` 上电 → 写 RAM → 恢复整窗 → `0x12` DRF。
- 档 1 的 768×552 内容 **1:1 落在 552 条可见栅极上**：不裁切、不重采样、无白边。
- 档 2 按控制器原生 800×600 渲染，会被可见区裁掉右 32 列 / 下 48 行，仅作对照诊断。
- 设置页「左右镜像」勾选框**只对档 2 生效**；档 1 行内固定正向，不看该开关。
- NVS 中遗留的旧档位值 `3` / `4`（已删除的交错相位档）在读入时**统归一到档 1**。
- **R1.5.4：档 2 能不能用由运行时缓冲决定，不再是无条件可选项。** 帧缓冲改为按当前画像分配，
  拿不到 120,000 字节连续空闲（本机最大块约 118 KB）时设备**自动退回档 1** 并照常开机，
  因此：`/api/info` 的 `a1_mode` 回报的是**生效档位**（`epd_get_a1_mode()`）而非 NVS 存量；
  `POST /api/settings` 在缓冲服务不了 800×600 时**拒绝存 `a1_mode=2`**。页面据生效档位选几何，
  不会构造出一个设备收不下的帧。

### 6.1 `/api/upload` 内容嗅探规则（固件 `sniff_kind()` ↔ 页面 `sniffKind()` 必须一致）

| 判据 | 依据 | 分流结果 |
|---|---|---|
| 首字节 == `0xE9` | ESP32 镜像魔数 | **固件**：预读首块 → 写另一 OTA 槽 → 校验 → 切槽 → 清页面热更标记 → 重置设置 → 重启 |
| 前 1024 字节（按 ASCII 小写）含 `<!doctype` 或 `<html` | HTML 文档开头 | **控制页**：收全量 → CRC32 校验 → 擦写 web 分区 → 提取版本 meta → 不重启 |
| 其它 | — | `400 unrecognized payload`，**判定前不擦写任何分区** |

- **不用** `Content-Type`（控制页为规避跨源预检，一律把文件包成 `text/plain` 的 Blob）
  **也不用**文件名（Blob 上传没有 `filename`）—— 多端（设备内嵌页 / 离线客户端 / 本地文件）
  行为必须一致，只有内容本身可靠。
- 固件预读**首块 ≥ 64 字节**用于判定；预读字节必须**原样**参与后续写入（丢文件头整包报废）。
- 固件升级的「同步更新控制页」在 R1.2.0 起是**默认行为**（原 `?sync_page=1` 的可选语义取消）。
- R1.1.x 的 `POST /api/ota`（含 `?sync_page=1`）与 `POST /api/web` 已**整体删除**，不做向后兼容。

### 6.2 `/api/carousel/*` 轮播 API（R1.4.0，FB-017 第二部分）

- **两级下标**：页面按**显示序 `i`**（0..n-1）操作，固件内部映射到**物理槽 `slot`**
  （0..7，来自 NVS `car_slot` 表）。`del` 只摘除显示项、**不擦槽**——槽由后续 `add`
  轮转复用；因此同一张图在不同时刻的 `slot` 可能不同，页面不要缓存 slot 语义。
- `list` → `{"on":1,"mode":0,"n":2,"cur":0,"slots":8,"int_s":1800,"next_in_s":900,"items":[{"i":0,"slot":5,"ok":true,"w":768,"h":552,"len":105984},{"i":1,"slot":2,"ok":false}]}`
  （`ok:false` = 槽头无效/损坏项，页面占位显示；`slots` = 分区可用槽位数，
  旧分区表 OTA 上来的设备为 0 = 不可用；`int_s` / `next_in_s` 为 R1.5.0 新增，见下「换图间隔」）。
- `frame?i=k`：返回该张的 **2bpp 原载荷**（无 16B 头；`Content-Type: application/octet-stream`
  \+ `Cache-Control: no-store`——载荷可能随删/存变化）。几何按 `len` 判定：
  `105984` = 768×552、`120000` = 800×600。错误：`400 bad index` / `404 no frame`。
- `add`：请求体 = `/api/frame` 同款帧（16B 头 + 载荷），先整帧收验再落盘。
  成功 `{"n":N,"slot":k}`。错误：`400 no store partition` / `400 carousel full`（8 张已满）/
  `500 slot write failed` / 帧级错误复用 `/api/frame` 的判定与文案。
- `del`：body `i=k`。成功 `{"n":N,"cur":j}`（`cur` 为摘除后当前张，可能被修正）。
  错误：`400 bad index`。仅摘除不擦槽（见上「两级下标」）。
- `advance`：立即换下一张（按当前模式），**异步**——回 `{"cur":j}` 时屏尚未刷新完，
  页面提示「屏幕刷新约数秒」。错误：`400 empty`（列表为空）/
  `500 no readable frame`（列表非空但无可读槽）。
- `cfg`：body `on=0|1&mode=0|1&int_s=秒`（`application/x-www-form-urlencoded`，**三键均可独立省略**，
  省略 = 不改）。成功 `{"on":1,"mode":0,"int_s":1800,"next_in_s":1799,"cal_off":0}`。语义修正（R1.4.0 末）：
  - `mode` 越界 → `400 bad mode`；
  - 解析后**所有键值与现状完全一致** → `400 no changes`（此前静默 200 / 语义漂移）；
    页面侧对此有双重处理：`carLast` 已知且值相同 → **就地确认不发请求**；
    未知窗口兜底读 400 响应体甄别 `no changes`（不误报「连接中断」）。
    **R1.5.2 起互斥副作用算一次改动**：`on=1` 且轮播本来已开、但日历本来也开着 → 不能回
    `no changes`（固件侧 `cal_off=1` 计入 `changed`），否则「顺手把日历关掉」这件事被吞掉。
  - `cal_off`（R1.5.2）= 这次保存**是否由设备端顺手关掉了日历**（`1` = 关了）。见 §6.3「日历 ⇄ 轮播互斥」。
- **换图间隔（`int_s`，R1.5.0）**：轮播换图节奏与「开热点等人」的 `wake_s` **彻底解耦**，
  独立存于 NVS 键 `car_int_s`（单位秒）。取值 `0` = 不自动换图，`60..86400` = 每隔多少秒换一张，
  越界回 `400 bad int_s`。页面把它呈现为「分钟」（0~1440，×60 后下发），与固件上限一致。
  - `list` / `cfg` 应答里的 `next_in_s` 是**设备自己的倒计时**：`0` = 该节奏未启用，
    `1` = 已到期，`>1` = 还要等的秒数。页面只转述这三个字段，不再拿 `wake_s` 推算
    （R1.4.0 的推算会说谎：换图真实时机还受空闲休眠影响）。
  - 手动「立即换一张」（`advance`）与 `cfg` 改间隔都会**重新锚定**下一次到期时刻（顺延一个完整间隔）。
- **触发时机**：轮播换图发生在**换图节奏到期**的那次定时唤醒（`car_int_s`）与页面「立即换一张」；
  到期唤醒只上屏、**不启动 WiFi**，若此时「开热点等人」未到点就立刻回深睡
  （轮播开着时日历已被设备关掉，见 §6.3 互斥，所以那次唤醒也不会为 SNTP 起 WiFi）。
  唤醒按钮（GPIO5）行为不变——仅管理唤醒，不换图。
- 旧固件（< R1.4.0）无此路由 → `404`，页面显式提示「此设备固件不含轮播功能
  （需 R1.4.0 及以上）」，无副作用。

### 6.3 `/api/time` + `/api/calendar/*` 日历 API（R1.5.0，功能1）

**时间口径（最重要的一条）**：设备只认「墙上日期」、不认时区。

- 页面打包：`t = Math.floor(Date.UTC(本地年, 月, 日, 时, 分, 秒) / 1000)`
  —— 即把手机屏幕上那个**本地读数当作 UTC** 的秒数。
- 固件：`settimeofday(t)`，读取一律 `gmtime_r()` 还原 → 还原出来的就是用户屏幕上的日期。
- 于是固件侧**零时区算法、零 civil-date 算法、NVS 不存日期基准**；`wd` = `tm_wday`（0 = 周日），
  与页面的 `["日","一","二","三","四","五","六"]` 以及日历网格表一致。
- 合理窗口 `1577836800 .. 4102444799`（2020-01-01 .. 2099-12-31）。窗口外 = 没同步过：
  `POST /api/time` 回 `400 bad time`，`synced` 为 0，日历**绝不拿 1970 上屏**；但 R1.5.3 起「没同步」
  不再等于「不参与定时」—— STA 已配时按退避窗口自醒重试校时（见下「自动校时」），没配联网才返回 `0`。
- **唯一的时区知识是一个偏移量**（R1.5.2）：`cal_tz`（秒，东为正，默认 `28800` = UTC+8），
  由页面在推日期时顺带告知（`tz_min`，分钟）。它**只服务于 SNTP**（见下「自动校时」），
  不参与页面推日期那条路径 —— 那条路径的 `t` 已经是伪 UTC，加偏移反而是错的。

**自动校时（SNTP，R1.5.2）**：设备自己把日期追平，不需要任何人打开页面。

- **为什么必须校**：板上没有 32.768 kHz 晶振，RTC 走内部 RC 慢时钟（`CONFIG_RTC_CLK_SRC_INT_RC`），
  日漂约 2 %（≈ 29 分钟）。不校时，它自己算的「00:01」会一天天前移，最后在大白天挂出**明天**。
- **两个时机，缺一不可**：① 正常启动（插电 / 按键 / 热点到期醒来）在 HTTP 服务起来之后
  一次性后台任务校时 —— 管「白天带走、晚上装上」；② **定时自醒路径**在校时前临时
  `netif_ap_init()` 起 WiFi、校完照旧立刻回深睡（不起热点、不进等待窗口）—— 管「固定时间」。
- **门槛**（`calendar_sntp_needed()`，四者全真才校）：日历开着 + STA 已配（`sta_enable`
  且 `sta_ssid` 非空）+（时钟不可信 **或** 距上次校时 ≥ 12 小时）。12 h < 每天一次自醒，
  所以每次换日醒来都会校一次；`s_sntp_at_s` 是 `RTC_DATA_ATTR`，掉电归 0 → 掉电那次必校。
- **服务器**：`ntp.aliyun.com` 主、`cn.pool.ntp.org` 备（`CONFIG_LWIP_SNTP_MAX_SERVERS=1`，
  串行降级）。阻塞但有超时：等 STA 拿 IP 10 s + 每台 12 s，**最坏约 34 秒**；全失败只是不校，
  不动时钟。需要路由器放行 **UDP 123**（下行）—— 被拦时表现为「日期还是靠页面推」。
- **没校上不许睡死（R1.5.3③）**：日历开着而时钟仍不可信时，`calendar_next_in_s()` 返回**退避窗口**
  （失败计数 `s_ntp_fail` 是 `RTC_DATA_ATTR`：1 小时起、每失败一次翻倍、**12 小时封顶**），
  设备因此会自己再醒一次重试，而不是三个节奏全 `0` → 无定时器深睡 → 永不自愈。
  校时成功即清零；STA 未配（`sta_enable=0` 或 `sta_ssid` 空）才返回 `0` —— 那是唯一「醒了也白醒」。
  失败次数经快照的 `ntp_try` 上报，页面把它译成人话（见下）。
- **换算**：lwip 的 `sntp_sync_time()` 是 **weak** 符号，默认实现直接 `settimeofday(真 UTC)`，
  那样屏上日期会整整差一个时区（在中国 = 少 8 小时，跨零点时挂在**昨天**）。固件覆盖它，
  落表 `settimeofday(真 UTC + cal_tz)`，即还原成伪 UTC 口径。应答换算后落在合理窗口外 → 丢弃、不改时钟。
- 校时成功后顺手 `catchup_today()`：「掉电重装 + 已过换日时刻」这种组合靠这一步补刷。

**状态快照 JSON**（`GET /api/time`、`POST /api/time`、`POST /api/calendar/cfg`、
`POST /api/calendar/show` 四个入口**同一份结构**，页面据此回显，不必二次拉取）：

```json
{"synced":1,"t":1791162462,"y":2026,"m":10,"d":5,"hh":1,"mm":7,"ss":42,"wd":1,
 "on":0,"tod_s":60,"lang":0,"style":0,"shown_day":20731,"next_in_s":0,
 "tz_min":480,"sntp_at":1268,"mono":1310,"ntp_try":0,"car_off":0}
```

- `synced` = 时钟可信；`t` = 当前伪 UTC 秒（未同步时为 0）；`y/m/d/hh/mm/ss/wd` = 还原后的日历读数。
- `on` / `tod_s` = NVS 里的日历开关与换日时刻（`tod_s` 自当天 00:00 起算秒数，默认 60 = 00:01，
  上限 `86399`，越界回 `400 bad tod_s`）。
- `lang` = 日历语言（`0` 中文 / `1` 英文，默认 `0`；**非 1 的值一律按 0 处理，不报错**）。
- `style` = 日历版面（`0` 暖纸 / `1` 红格 / `2` 翻页牌 / `3` 打卡点阵，默认 `0`；
  `lang` 仍是非 1 按 0 钳位，`style` 是越界按 0 钳位，两者都不报错）。
  后两个键 R1.5.0 之前的固件应答里没有 —— 页面据此**不回卷用户已选的下拉**，只在下次保存时补发一次。
- `shown_day` = 已渲染过的「天号」（`epoch 秒 / 86400`），`-1` = 还没渲染 / 未锚定（**已落 NVS**，见 §7）。
- `next_in_s` = 设备自己的换日倒计时，沿用 §7 的多节奏约定 `0` 未启用 / `1` 已到期 / `>1` 还要等的秒数。
  **页面只转述、不推算**；`1` 译成「已到换日点」而不是「还剩 1 秒」。
- `tz_min`（R1.5.2）= 当前生效的时区偏移（分钟，东为正），就是 `cal_tz / 60`，供页面回显「时区 UTC+8 已写入」。
- `sntp_at`（R1.5.2）= 上次校时**成功的单调时刻**（`power_mono_s()` 口径，`0` = 本次开机还没校过）。
- `mono`（R1.5.2）= 设备**现在**的单调秒数，与 `sntp_at` 同一基准 —— 页面算 `mono - sntp_at` 就是
  「距上次校时多久」。**两者必须配对使用**：单调秒从开机起算，跨设备、跨重启都不可比。
- `ntp_try`（R1.5.3）= 本次开机以来自动校时**连续失败**的次数（成功即清零）。`synced=0` 且此键存在 →
  页面把 `next_in_s` 译成「约 X 后自己再试校时」，`>1` 时补一句「已连续失败 N 次」；
  **键缺失 = R1.5.2 及更早的设备根本不会自己重试**，页面必须显式说「日期没同步时不会自动改日期」，
  **不得**把 `undefined` 当成 0 去显示「已连续失败 0 次」。
- `car_off`（R1.5.2）= 这次保存是否由设备端顺手关掉了相册轮播（只在 `/api/calendar/cfg`
  的成功应答里为 `1`；`GET /api/time` 等入口恒为 `0`，因为读操作不带副作用）。
- **旧固件降级**：R1.5.1 及更早的应答里没有 `tz_min` / `sntp_at` / `mono` / `car_off` 四个键，
  R1.5.2 的应答里没有 `ntp_try`。页面必须按「键缺失 = 设备不报」处理：不声称写入了时区、
  不声称关掉了轮播、**不把指数退避重试说成已生效**、状态行显式说明
  「此设备固件不含自动校时（需 R1.5.2 及以上）」。**不要**把 `undefined` 当成 0 去算年龄或失败次数。

**路由语义**：

- `POST /api/time`（body `t=秒&tz_min=分钟`，**`tz_min` 可省略** = 保持当前偏移）：`settimeofday()`
  成功后把「今天」记成已锚定，回状态快照。`tz_min` 越界（`±840` 分钟之外）→ **忽略该键、保留原偏移**，
  日期照常写入（屏上日期对不对比时区对不对重要得多，不为此回 400）。
  错误：`400 missing t` / `400 bad time` / `500 clock set failed`。
- `POST /api/calendar/cfg`（`on=0|1&tod_s=秒&lang=0|1&style=0..3`，**四键均可独立省略** = 不改）：成功回状态快照。
  与轮播 `cfg` 同一套守卫：解析后所有键值与现状完全一致 → `400 no changes`；`tod_s` 越界 → `400 bad tod_s`。
  **互斥副作用计入 `changed`**（同 §6.2）。改时刻的语义：当天**已刷过则保持**，未刷过则按新时刻重新判到期（`next_in_s` 自算）。
  **改语言或改样式的语义**（两者同为「版面」参数）：`cal_on` 为真 → 立刻按新版面异步重排当前画面
  （等同一次 `show`，15~25 秒）；为假 → 只写 NVS、**不碰屏幕**。
- `POST /api/calendar/show`：**异步**上屏当天日历（整屏刷新 15~25 秒，不能挂在 HTTP 应答上）。
  错误：`400 clock not set`（先同步日期）/ `500 draw failed`。成功回状态快照（`shown_day` 已更新）。
- 四条路由都是 `power_activity()` 开头（碰了就重新计空闲休眠）。

**日历 ⇄ 轮播互斥（R1.5.2，由固件强制）**：两者抢同一块屏，只能有一个主人。

- `POST /api/calendar/cfg` 保存后 `cal_on=1` → 设备调 `carousel_set_off()` 关掉轮播，应答 `car_off:1`；
  `POST /api/carousel/cfg` 保存后 `on=1` → 设备调 `calendar_set_off()`，应答 `cal_off:1`。
- **只有关的那一侧动手**：关掉轮播不碰日历，删帧 / `advance` 也不碰日历；`on=0` 时不触发互斥。
- **开机兜底**：R1.5.1 及更早允许两个同时开，升到本版后第一次开机若发现同开，
  按「日历开着 = 屏幕归日历管」**保留日历、关掉轮播**（`calendar_init()` 在 `carousel_init()` 之后跑）。
- 页面据此**反向刷新另一个 tab 的复选框**（`car_off` → `carRefresh()`、`cal_off` → `calRefresh()`），
  并把设备回告的事实写进就地药丸 —— 不是页面自己猜「你可能也想关另一个」。

**开日历即夺屏（关键行为约定，R1.5.1 方案 B 起）**：

- 开启 `cal_on` **会**立刻把今天刷上屏（配置接口里 `turned_on` → 异步 `calendar_show(1)`，
  页面药丸提示「今天这张正在上屏（约 15~25 秒）」）。此前 R1.5.0 的「开日历不抢屏、当天首刷只能
  靠用户点『立即显示今天』」已废除 —— 用户实际用法是日历与轮播二选一，开着日历就是要把屏交给它。
- 补刷的三个入口（`catchup_today(force)`，幂等）：开机（`frame_init()` 之后）、页面推来日期、
  换日时刻到点而设备正醒着（`idle_monitor_task` 每秒 `calendar_awake_tick()`）。
  **缺哪一天补哪一天**，天号落 NVS，所以按键唤醒不会每次重刷同一张日历。
- **屏上内容未知 = 强制补刷（R1.5.3①）**：`cal_day` 只回答「今天刷过没有」，**不回答「屏上现在挂着什么」**。
  墨水屏是双稳态的，断电 / EN 复位 / OTA 重启后画面原样保留，而 NVS 里的天号仍是今天 —— R1.5.2 因此出过
  「同一天断电重上电，日历再也不回屏」的现场故障（用户把 todolist 推上屏后断电重上电：`cal_on=1`、
  `cal_tod_s=60`、`cal_day=20732` = 当天，补刷被 `s_shown_day == today` 直接挡掉，与 SNTP 成不成功无关）。
  修复判据是唤醒原因：开机读 `power_wakeup_causes()`，**非深睡唤醒就 `calendar_boot_catchup(1)` 无条件把当天
  强制上屏一次**；深睡唤醒画面没被动过 → 传 `0`，照旧只补缺的那天。
  ※ **R1.5.5 修的就是这个判据**：IDF 对上电 / EN 复位 / OTA 重启返回的不是 `0`，而是置了
  `BIT(ESP_SLEEP_WAKEUP_UNDEFINED)` 的**位图**（该枚举是 0 ⇒ 位图恒为 1），所以 R1.5.3~R1.5.4 写的
  `wake == 0` **恒假**，这条强制补刷从没生效过。现在是按位判断
  `(wake & (1u << ESP_SLEEP_WAKEUP_UNDEFINED)) != 0`。
- 「立即显示今天」退成手动重刷的兜底。
- **天号只在成功上屏后记录（R1.5.3②）**：R1.5.2 是「无论成败都记为已处理」，于是绘制 / 送屏一失败
  这一天就再也不补。本版把记录挪到成功分支；为防「失败 → 天号仍空 → `calendar_awake_tick()` 每秒重敲屏」
  的连刷风暴，另加一个 **RAM-only 的 `s_try_day`**（本次开机已尝试过的天号）：每次开机对同一天**只试一次**，
  失败留给下一次开机或下一次换日，跨秒不重复刷。
- 一次定时唤醒**只做一件事**，日历优先于轮播（`main.c` 派发顺序）；有了上面的互斥，
  同开状态不再可能持久存在，「换日被下一次换图盖掉」从根上消失。
- 页面启动时若 `synced=0` 会**静默补一次日期**（只更新回显、不弹提示，并顺带把手机时区写进去），
  掉电重上电后无需手动操作；开着「启用联网」时设备自己也会经 SNTP 追平（见上）。

**画面**：`cal_face_draw()` 在 768×552 的 2bpp 帧上直接写**竖版**日历（逻辑画布 552 宽 × 768 高，

### 6.4 `/api/todo` 待办清单 API（R1.5.0，功能3）

**设备是这份清单的持久层，不是渲染器。** 任意中文只有页面画得出来（固件里只有离线烘焙的字模表），
两套待办版式（A 横线条目表 / B 红色时间轴）与 2bpp 帧的合成全在浏览器完成，
合成好的画面仍走既有的 `POST /api/frame` —— 与传图同一条链路，**帧契约不变、`api` 不 +1**。

| 方法 | 请求 | 应答 |
|---|---|---|
| GET | — | 当前文档原文（`application/json`，从未写过 = `{"v":1,"style":0,"lang":0,"push":1,"done":[],"items":[]}`） |
| POST | body = 整份文档原文 | 成功回**同一份原文**；页面用「提交串 == 回读串」判断是否真的落盘 |

- 文档字段（语义全在页面，设备不解析）：`v` 结构版本 / `style` 版式（0 = A 横线条目表、1 = B 红色时间轴）/
  `lang` 牌头语言（0 = 中文、1 = English，只管日期与「已完成」这类固定文字）/ `push`（1 = 勾选即上屏）/
  `items[]` 条目文本 / `done[]` 与 `items` 同长的 0/1 完成标记。
  **真源在设备**：换一台手机打开控制页，读回的是同一份清单与同一个勾选进度。
- 设备只把三道**字节闸门**：长度 `1..1536`；必须是 JSON 对象（首 `{` 尾 `}`）且含键 `"items"`；体里不含 NUL。
  越界 / 结构不符 → `400 bad doc` / `400 doc too large`，NVS 与内存态都不动；
  写 NVS 失败 → `500 store failed` 且**不换内存镜像**（页面因此不会「回显成功、重启就丢」）。
- 上限 1536 B 的理由：`nvs` 分区只有 16 KB。12 条 × 20 汉字（UTF-8 ≈ 60 B/条）加头尾实测 ≈ 760 B，
  取 1536 B 已留近一倍余量；再高就要动分区表。
- **待办不进轮播**（用户 2026-10-05 定）：与 `car_*` 键、与定时唤醒都没有交集 —— 用户改一次、它上屏一次，
  设备不会自己醒来换清单。固件升级不重置（`settings_reset_for_upgrade()` 白名单擦键），恢复出厂随命名空间清空。
- 旧固件（< R1.5.0）无这两条路由 → `404`，页面在读取与两个操作入口统一提示
  「设备固件不含待办功能（需 R1.5.0+ 固件）」，条目区换成升级指引，不假装能用。

## 7. 设置与 NVS

- 命名空间 `moink`；键 `panel` / `hflip` / `a1_mode` / `wifi_pwr` / `sleep_s` / `wake_s` /
  `ap_ssid` / `ap_pass` / `sta_enable` / `sta_ssid` / `sta_pass` /
  **`car_*`（轮播，见下）** / **`cal_on` / `cal_tod_s` / `cal_lang` / `cal_style`（日历，见下）** /
  **`todo_doc`（待办清单整份文档，见下）**
  （`page_ver` 为控制页热更标记，由 `ota_web.c` 维护）。
- **固件升级强制重置**（R1.2.0）：OTA 校验通过、切槽之后调用 `settings_reset_for_upgrade()` ——
  它是**白名单擦键**，只擦 `panel` / `hflip` / `a1_mode` / `wifi_pwr` / `sleep_s` / `wake_s` **这 6 个**
  并回落默认值（`src/settings.c` 里的 `KEYS[]`）。其余键**天然保留**：热点凭据与 STA 凭据是为了
  避免「改了热点名 / 联网的设备升级后失联、再也连不上」，`car_*` / `cal_*` 则是用户已配好的节奏，
  升级不该把轮播列表和日历设置清空。另有 `ota_web.c` 清 `page_ver` 热更标记（见 §6.1）。
- **恢复出厂**（长按唤醒键 5s / `POST /api/factory`）：`nvs_erase_all()` 擦除整个 `moink`
  命名空间（含 `page_ver` 热更标记，即页面一并回退内嵌版），轮播另走 `carousel_factory_wipe()`
  清空 store 槽位；日历开关与时刻随命名空间一起清空。
- 休眠档位（`sleep_s`）：`0`=不休眠 / `60` / `180`（默认）/ `300` 秒。
  **`0` 不等于永不入睡**（R1.5.0）：只要开了任一节奏（`wake_s` / `car_int_s` / 日历 `cal_on`），
  空闲 3 分钟后仍会深睡——否则定时器没被武装，节奏一次也不会触发。
- 自动唤醒间隔（`wake_s`）：`0`=关（默认），否则**任意 1~86400 秒**。R1.5.0 起不再限于
  1/12/24 小时三档，页面按「分钟」（0~1440）填写、×60 下发。语义 = 「醒来**开热点等人传图**」的节奏
  （轮播换图改用 `car_int_s`，见 §6.2）。
- **多节奏武装（R1.5.0）**：入睡时取各节奏中**最近的一个到期时刻**武装 RTC 定时器
  （`power_next_wake_s()` = `min(power_hotspot_in_s(), carousel_next_in_s(), calendar_next_in_s())`，
  最短武装 `MIN_ARM_S` 30 s 防抖）。三个节奏是「开热点等人」`wake_s`、「轮播换图」`car_int_s`、
  「日历改日期」`cal_on` + `cal_tod_s`。各节奏查询函数统一约定返回值
  `0` = 未启用 / `1` = 已到期 / `>1` = 距到期秒数；到期者干活，未到期者不打扰（不开热点）。
  **时钟不可信时日历不参与换日，但不许睡死**（R1.5.3③）：`synced=0` 且 STA 已配 → 返回
  1→2→4→8→12 小时封顶的退避窗口，让设备再醒一次去试 SNTP；STA 未配才返回 `0`。
  理由很硬：三个节奏全 `0` 时是「不武装定时器直接深睡」= 设备永远不会自己醒，
  「回来装上就自己追平」这条承诺当场失效。无论哪种情形都**绝不拿 1970 上屏**。
  跨深睡的秒数由 `RTC_DATA_ATTR` 累加器提供（C3 的 `esp_timer_get_time()` **不跨深睡走时**），
  断电重上电后归零，节奏从「刚开机」重新起算。
- **到期醒来后做什么（R1.5.1 / R1.5.2）**：`auto_wake` 路径的顺序是契约，不能反 ——
  ① 日历需要校时则先 `netif_ap_init()` 起 WiFi（**只起 WiFi，不起 HTTP、不进热点等待窗口**）
  跑完 SNTP；② `calendar_boot_catchup(0)`（深睡唤醒画面没被动过 → 不强制刷，只补缺的那天）；
  ③ 各到期节奏干活（日历换日 → `calendar_boot_tick()`，
  轮播 → 换一张）；④ 若热点节奏同时未到期则**立刻回深睡**。顺序理由是 RTC 走内部 RC 慢时钟，
  不校时就会用漂掉的时钟判断「今天到点没有」；先刷再校正等于白刷一遍屏。
  校时把时钟往回拉、换日其实还没到时 → 落回正常启动（宁可多醒一个空闲窗口，不加第二条睡路）。
- **入睡与 STA 的先后（R1.5.1，日历能否换日的根因）**：`power_enter_deep_sleep()` 先立闸门
  `netif_sta_suspend_begin()` 再 `esp_wifi_stop()`；断线回调看见闸门就**不重连**（此时驱动已停，
  重连必失败 → 旧版 `ESP_ERROR_CHECK` abort → 复位 → 每 3 分钟一个循环，定时器永远走不到武装那步）。
  非入睡的正常掉线仍自动重连，且重连失败只打 warning。
- **热点凭据单字段更新（FB-014①，R1.2.0）**：POST `/api/settings` 时 `ssid` / `pass` 任一键
  **缺省 = 保持当前值**；`pass` 空串 = 清除密码（热点转开放）。页面据此把「留空」表达为
  不发送 `pass`、「清除密码」表达为显式发空串（仅已设密码时显示该勾选）。
- **热点配置延迟应用（FB-014②，R1.2.0）**：`settings_post_handler` **先发 `200` 应答**，
  300 ms 后经 esp_timer 一次性回调再 `netif_ap_apply()`（踢客户端）。改名 / 改密码场景
  页面可以正常收到成功应答。
- 热点：SSID 空 → 默认 `MoInk-XXXX`（XXXX = MAC 后 2 字节）；密码空 → **开放**。
  AP 通道 **6**（避开 ESP32-C3 40MHz 晶振落在 2.4 GHz 低段的谐波，见 FB-001），最多 4 客户端，
  DHCP DNS 指向 `192.168.4.1`。
- **STA 联网（R1.3.0）**：`sta_enable`=1 且 `sta_ssid` 非空时设备以 station 身份连入路由器
  （APSTA 共存），经 DHCP 拿到局域网 IP（`/api/info` 的 `sta_ip`）。`sta_pass` 不回显，
  页面用 `sta_pass_set` 标志位表示「是否已设密码」。STA 掉线自动重连；AP 热点始终保留兜底。
  恢复出厂的 `nvs_erase_all()` 会一并清空 STA 凭据。
  **R1.5.2 起 STA 还是自动校时的唯一出口**：只有 STA 已配，日历才会在醒来时走 SNTP（需路由器放行 UDP 123）。
- **轮播键（R1.4.0）**：`car_on`（开关）/ `car_mode`（0 顺序 / 1 随机）/ `car_int_s`（换图间隔秒数，
  `0` = 关，R1.5.0 新增）/ `car_n`（张数）/ `car_slot`（blob：显示序 → 物理槽映射）/ `car_cur`（当前张显示序）/ `car_wseq`（写槽轮转游标）。
  **固件升级不清除**（`settings_reset_for_upgrade()` 为白名单擦键，`car_*` 天然保留）；
  **恢复出厂** `nvs_erase_all()` 连同 `carousel_factory_wipe()` 一并清空 store 全部槽位。
- **日历键（R1.5.0，共六个）**：`cal_on`（u8，开关，默认 `0`）/ `cal_tod_s`
  （u32，换日时刻自当天 00:00 起算秒数，默认 `60` = 00:01，上限 `86399`）/ `cal_lang`
  （u8，0 = 中文、1 = 英文，默认 `0`）/ `cal_style`（u8，0 = 暖纸、1 = 红格、2 = 翻页牌、3 = 打卡点阵，
  默认 `0`；`lang` 写入与读回时非 1 归 0，`style` 越界归 0，都不报错）。
  - `cal_day`（i32，**R1.5.1**）= 已**成功**上屏的「天号」，即 API 里的 `shown_day`。
    **R1.5.3 起它只回答「今天刷过没有」，不回答「屏上挂着什么」**（见 §6.3「屏上内容未知 = 强制补刷」）。
    原先放 `RTC_DATA_ATTR`，**崩溃 / 复位就清零**，于是 `anchor_today()` 反过来把当天误记成已处理，
    日历从此不换日（现场证据 `shown_day:20732 / next_in_s:85614`）—— 落 NVS 才跨复位、跨掉电有效。
  - `cal_tz`（i32，秒，东为正，**R1.5.2**）= 时区偏移，SNTP 换算专用（见 §6.3）。默认 `28800` = UTC+8；
    写入来源是页面 `POST /api/time` 的 `tz_min`（× 60），`±50400`（±14 h）之外视为非法、保留旧值。
    **固件里没有任何 DST / 地区规则** —— 偏移就是手机那一刻告诉它的值，跨时区旅行后重推一次日期即更新。
  - 「上次自动校时的单调秒」`s_sntp_at_s` **不进 NVS**，是 `RTC_DATA_ATTR`：掉电归 0 正是想要的
    （掉电后时钟也回 1970，那次开机必被判定需要校时）。因此 `sntp_at` / `mono` 只在本次开机内可比。
    R1.5.3 的退避档位 `s_ntp_fail` 同一口径（掉电归 0 = 退避从 1 小时重新开始）；补刷去抖用的
    `s_try_day` 是普通 `static`，复位即丢 —— 每次开机对同一天都允许再试一次。
  与 `car_*` 一样：**升级保留、恢复出厂清除**（`settings_reset_for_upgrade()` 的白名单只擦
  6 个显示 / 休眠参数，`cal_*` 全不在列）。见 §6.3。
- **待办文档键（R1.5.0）**：`todo_doc`（字符串，页面写来的整份 JSON 原文，上限 1536 B）。
  设备端零解析 —— 不认条目内容、不认版式，只认结构骨架（见 §6.4）。
  与 `car_*` / `cal_*` 一样：**升级保留、恢复出厂清除**。
- 页面自身所有画面参数（风格 / 强度 / 文字 / 旋转 / 方向 / 首页停在哪个内容 tab）一律存于手机
  `localStorage`（key `moink.cfg4`，历史键自动一次性迁移），**固件不存、不回读**。
  唯一例外是待办清单：它的真源在设备 `todo_doc`（`localStorage` 只在「未连设备的本地预览」模式下用）。

## 8. 版本号与升级流程（R1.2.0 起）

- **单一版本号**：固件与控制页**共用** `MOINK_VERSION` 一个号（不再有 fw / page 两套）。
  运行时 `/api/info` 的 `ver` = **当前生效的控制页版本** —— 热更页在用时取它的
  `<meta name="moink-page-version">`，否则等于 `MOINK_VERSION`。因此恒有 `ver ≥ fw`。
  `fw` 字段保留一版，**仅供**前端判断「热更控制页是否落后于固件」（落后时状态栏红字警示）。
- **升级统一走 `POST /api/upload`**（§6.1）：用户只上传一个文件，固件按内容分流。
  固件升级会**顺带更新控制页并重置 6 个显示 / 休眠参数**（§7 白名单；热点名、联网凭据、
  轮播与日历配置都保留）；控制页升级只换页面、不重启。
- **★ OTA 自确认窗口与自动回滚（R1.5.4 定案；`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`）**：
  新镜像首次启动后 **12 秒**（`OTA_CONFIRM_MS`）由后台任务调用
  `esp_ota_mark_app_valid_cancel_rollback()` 取消回滚；幂等版本 `ota_web_confirm_flush()` 还被
  **`power_enter_deep_sleep()` 的第一行**调用 —— `esp_deep_sleep_start()` 永不返回，**深睡等价于一次复位**，
  不先确认就会被盖 ABORTED。窗口内任何复位 / 断电 / 崩溃 → bootloader 在第二次启动给该槽
  stamp **ABORTED**，此后**永久跳过**它并回落到旧槽，且**不产生任何错误应答**（用户侧只看到
  「升级成功、版本还是旧的」）。因此本版把 `ota_web_confirm()` 排到 `frame_init()` 成功后**立即起算**
  （旧版排在一大串外设初始化之后，窗口白白被吃掉），窗口从 45 秒缩到 12 秒，并把两个槽的
  状态经 `/api/info` 的 `ota_*` 四字段暴露 —— 页面「系统维护与升级 → 升级状态」直接说出
  「上次升级没确认成功，已被自动退回」。
- **`api`（帧格式契约号）与发布版本号解耦**：只在 §1–§3 帧契约变化时 +1，与 `version` 无关。
- **防漂移门禁**：固化内嵌页前 `tools/make_index_header.py` 断言
  `page/index.html` 的 `<meta moink-page-version>` == `src/version.h` 的 `MOINK_VERSION`，
  不一致直接失败（打印两边实际值），从机制上杜绝「页面改了、版本号没跟」。
- 回归门禁（必须全绿）：
  - `python tools/check_frame.py`（帧契约黄金校验）
  - `node tools/smoke_page.js`（页面纯函数 + 帧头 + 旋转 + 文字层几何）
  - `node tools/_r110_regress.js`（768×552 老路径零回归：`crc16` / `rotateCW` / `packIdx` /
    帧头与基线 `page-R1.0.26.html` 逐字节一致）
  - `python tools/check_algo.py`（算法冻结，12 函数逐字 MATCH）

## 9. 分区表与存储（R1.2.0 起有变，FB-017 第一部分）

- **4 MB 布局**（`partitions.csv`）：

| 名称 | 类型 | 偏移 | 大小 | 用途 |
|---|---|---|---|---|
| nvs | data/nvs | 0x9000 | 16 KiB | 设置（不变） |
| otadata | data/ota | 0xD000 | 8 KiB | OTA 启动选择（不变） |
| phy | data/phy | 0xF000 | 4 KiB | 射频校准（不变） |
| ota_0 / ota_1 | app | 0x10000 / 0x150000 | **1.25 MiB ×2** | 固件双槽（1.5→1.25 MiB） |
| web | data/spiffs | 0x290000 | **384 KiB** | 控制页热更（960→384 KiB） |
| **store** | data/spiffs | 0x2F0000 | **1,088 KiB** | 轮播帧存储（R1.2.0 预留，R1.4.0 起实际读写） |

- **★★ 升级到 R1.2.0 必须整包线刷（`merged.bin` 含新分区表），不能从旧版本 OTA**：
  分区表只能由线刷改写；旧表设备 OTA 本版 app.bin 后可开机（`store` 缺失 →
  `store_slots=0`，其余功能不受影响），但不受支持。自 R1.2.0 起（同分区表）恢复正常 OTA。
- **store 槽位布局**（`src/store.c`）：8 个固定 **128 KiB** 槽位（0x110000 / 0x20000）+
  64 KiB 预留；单槽容纳最大帧 800×600 2bpp = 120,000 B（768×552 = 105,984 B）。
  槽内 **16B 头**：magic `MST1` + w/h（u16 LE）+ len（u32 LE）+ 载荷 CRC16/CCITT-FALSE
  （u16 LE）+ 2 保留；**头无效（从未写过）= 空槽**。
  **R1.5.4：`store_slot_read(slot, buf, cap, meta)` 多带一个 `cap`** —— 槽内字节数大于运行时缓冲
