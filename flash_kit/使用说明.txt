墨印 MoInk 一键刷机包
版本：R1.5.5（固件与控制页共用同一个版本号；2026-10-06，api 保持 2）
================================================

本版解决的是「**断电重上电后屏幕不回日历**」—— 这条判据 R1.5.3 就写进代码了，但实机上一直不生效。
根因不在硬件、也不在显示链路，是一行判错的唤醒原因：
  ① 开机那句 calendar_boot_catchup(wake == 0) 的实参**永远为 false** —— ESP-IDF 对
                  「掉电重上电 / EN 复位 / 升级重启」返回的是**位图**，UNDEFINED 这一位恒被置上
                  （BIT(0) = 1），所以 wake 永远等于 1、永远不等于 0。
                  R1.5.5 改为按位判断，「屏上内容不可信」这件事才第一次真正传到日历模块。
  ② 于是掉电 / 复位 / 升级后的那次开机**强制把当天日历回屏一次**：墨水屏断电不掉图，
                  设备自己看不见屏上留着的是旧画面，只能无条件重刷一次。
  ③ 控制页日历卡片的「自动校时 · 尚未自动校时」是**假阴性**：sntp_at 上报的是单调量，
                  页面若在校时完成前读一次就误判成「从没校过」。R1.5.5 起开页最多**补读一次**
                  （12 秒后），并明确禁止轮询 —— 每次请求都会喂 power_activity，把深睡彻底废掉。
  ④ 「校时的原理与边界」这类长说明收进折叠块，日历卡片常驻只留一句：
                  开着「启用联网」时设备自己把日期校准，**不必**再手动点「同步今天日期」。

沿用的 R1.5.x 能力（本版未改）：
  · 日历自动改日期（四套版面：暖纸 / 红格 / 翻页牌 / 打卡点阵，中英双语，法定节假日自动标记）
  · 待办清单上屏（清单存在设备里，换手机读回同一份；取代原「便签」）
  · 首页三个内容 tab（拍立得 / 待办 / 轮播）+ 三个独立唤醒节奏（开热点等人 / 轮播换图 / 日历改日期）
  · R1.5.3 修的三件事：日历画失败不记天号、没校上时按 1→2→4→8→12 小时退避重试、退避信息回显
  · R1.5.4 修的三件事：帧缓冲按画像分配且分配失败不自杀、自确认窗口缩到 12 秒且深睡前兜底确认、
                  回滚在页面上可见（「升级状态」药丸 + 「帧缓冲」读数）

★ 升级窗口（仍然存在，别踩）：网页升级后设备重启，**重启完成后约 12 秒内不要断电、
   不要按键、不要拔 USB** —— 这一刻新固件还没完成自我确认。踩到窗口不会报错，只是被自动退回旧版；
   判断有没有踩到，看控制页「设置 → 系统维护与升级 → 升级状态」：显示 **ABORTED** 类文案就是被退回了。
★ 补救（不用重刷）：在该页确认「升级状态」是回滚态后，重新上传一次 moink_R1.5.5_app.bin 即可
   （切槽会把该槽重新标记为可启动）；或者按下面的方式 C 直接写正在启动的槽。
★ 整包 moink_R1.5.5_merged.bin 从 0x0 写入会**连带擦掉 NVS**：待办清单、日历开关与样式、
   局域网账号密码全部丢失。除非设备已经刷歪，否则别用整包。
★ 本版起「刷了没生效」多一个可见线索：掉电重上电后屏幕**没有**自己回到当天日历，就说明跑的还是
   R1.5.4 及更早的镜像（①那条修复没进去）。先确认版本，再谈功能。

方式 C：只换 app 槽，设置一个都不动（本版实机就是这么装的）
  1. 数据线接电脑，按一下板子按键或拔插一次 USB 让设备醒来
     （C3 深睡时电脑看不到串口，必须先让它醒）。
  2. 在本目录终端里执行（串口名换成你机器上的）：
       python3 -m esptool --chip esp32c3 -p COM7 -b 921600 \
           write_flash 0x10000 moink_R1.5.5_app.bin
     0x10000 = ota_0；既不碰 0x9000 的 NVS，也不碰 0xd000 的 otadata，
     所以不走自确认、没有回滚风险，且**不会**重置那 6 项显示 / 休眠参数。
     ※ 不确定设备在跑哪个槽时，把同一个 app.bin 也写到 0x150000（ota_1）：
        两个槽内容一致，bootloader 选哪个都是本版，NVS / 相册 / 页面分区都不动。
  3. 刷完拔插一次 USB，打开设备页，版本应显示 R1.5.5，且「升级状态」为绿色已确认。

文件夹内容（放在同一个目录）：

  moink_R1.5.5_app.bin     OTA 升级包（设备已能开机时，在网页里上传 / 方式 C 线刷）
  page-R1.5.5.html         控制页（网页里「② 只更页面」上传，免刷机）
  test_frame_post.py       诊断工具（PC 直连发四色测试帧，验证显示链路）
  ※ 本包（GitHub 仓库里的 flash_kit/）只放**当前版本 R1.5.5** 的产物；如果你手上的目录里
     还留着 moink_R1.5.3_* / moink_R1.5.4_* / page-R1.5.3.html / page-R1.5.4.html，那是历史版本：
     R1.5.3 的 app.bin 刷进设备会因为帧缓冲申请失败而起不来，
     R1.5.4 起得了开机自杀但没有本版①②的强制回屏 —— 一律用上面的 R1.5.5 文件。

怎么升到本版
------------------------------------------------
【推荐】方式 A：设备现在跑 R1.5.0 / R1.5.2 / R1.5.3 / R1.5.4，网页里直接升
  1. 控制页「设置 → 系统维护与升级 → ① 升级」，把 moink_R1.5.5_app.bin 选进去
  2. 等设备重启完成（约 1 分钟），**重启后 12 秒内不要断电 / 按键 / 拔 USB**
  3. 重启后页面自动变成新版（控制页随固件一并更新），版本显示 R1.5.5，
     「升级状态」显示「已确认，不会被回滚」
  ※ 网页升级会把这 6 项打回默认（屏幕档位 / 左右翻转 / A1 写入模式 / WiFi 功率 / 休眠档位 /
     自动唤醒=关闭），而方式 C 线刷不会 —— 在意「休眠档位」的走方式 C。

方式 B：需要整包刷写 / 首次使用
  1. 如果这台电脑没有 Python，双击 MoInk一键刷机.bat 会询问「是否自动下载并安装」，
     输入 y 回车即可。
  2. 用【数据线】（能传数据的，不是纯充电线）把板子接到电脑 USB 口。
  3. 双击 MoInk一键刷机.bat，等它自动选串口、自动刷写（约 1~2 分钟）。
     脚本只认带 VID 的真实 USB 串口，蓝牙等虚拟串口（无 VID）会自动跳过。
  4. 看到 [OK] 刷机完成即可。手机 Wi-Fi 连 MoInk-XXXX（默认开放）→
     浏览器打开 http://192.168.4.1

※ 方式 B 会整体覆盖设备上的现有固件与设置：待办清单、日历开关与样式、局域网
   账号密码会被一并清空（整包在 NVS 区域填的是空字节）。
※ R1.1.x 及更早版本的设备必须走方式 B（线刷）：分区表不同，不能直接 OTA。

★ 网页里升级只需选文件，不用判断类型
------------------------------------------------
R1.2.0 起只有一个升级入口，本版沿用：
  · 传 moink_R1.5.5_app.bin（.bin）→ 固件升级：写备用分区 → 校验 → 切槽
    → 顺带更新控制页 → 重置 6 项显示/休眠参数 → 自动重启
    （保留：热点名/密码、局域网配置、轮播画面、轮播与日历设置、待办清单）
  · 传 page-R1.5.5.html（.html）→ 只热更控制页：CRC32 校验 → 替换
    → 不重启，刷新浏览器即可
设备按文件**内容**识别（固件首字节 0xE9 / 页面以 <!doctype 或 <html 开头），
不看后缀名，也不看浏览器报的类型。
※ 只热更页面（不升固件）时，「升级状态」与「帧缓冲」会显示「—」—— 这是预期行为：
   这两项数据来自 R1.5.4+ 固件，旧固件不上报。
※ 热更页面会**盖住**固件内置页：想把设备恢复成随固件编译进去的那一份，
   点设置页「① 升级」下方的「恢复内置页面」。

注意事项
------------------------------------------------
- 不要用浏览器网页烧录器！本板是 C3 原生 USB-JTAG（VID 0x303a），
  网页烧录器（WebSerial）会卡死在 "Stub running..."，一个字节都写不进。
- 如果卡死或失败：拔插一次 USB，然后在本目录打开命令行运行：
      python flash_on_pc.py --no-stub
- 查看本机全部串口：
      python flash_on_pc.py --list
- 网页升级会重置这 6 项：屏幕档位 / 左右翻转 / A1 写入模式 / WiFi 功率 / 休眠档位 /
  **自动唤醒（回落「关闭」）**。热点、联网、轮播、日历设置都不动；方式 C 线刷一项都不动。
- 「不休眠」不等于永不入睡：开了任一节奏（开热点等人 / 轮播换图 / 日历改日期）时，
  空闲约 3 分钟后设备照样深睡 —— 本版起**每次入睡都会先确认新固件**，不再因此被回滚。
- **A1「写入模式」的 800×600 对照档（档 2）在本机不可用**：它需要 120,000 字节连续内存，
  而设备最大连续空闲块只有约 116 KB。选了也会被固件退回档 1（768×552 顺序），
  设备照常工作；`/api/info` 里的 `a1_mode` 报的是**生效档**，页面按它选几何，不会构造出收不下的帧。
- 日历需要**日期同步**：设备断过电日期就丢了。R1.5.5 的口径是 —— 只要「启用联网」是开的，
  开机、到点自醒都会**先走 SNTP 校时（ntp.aliyun.com，失败再试 cn.pool.ntp.org）再决定换日**，
  一次也没校上时按 1→2→4→8→12 小时退避自己醒来重试，不会因为一次失败就睡死；
  路由器需放行 UDP 123。校时靠的是局域网，不是热点，所以手机不必一直连着设备。
- 刷完 / 复位后设备时钟会回到 1970，**不用手动点「同步今天日期」**：开着联网它自己校；
  没开联网时，重新打开一次设备页会立刻用手机日期补回。
- 日历与相册轮播**互斥**（R1.5.2 起由固件强制）：开日历会自动关轮播，反之亦然，
  同一块屏只有一个主人，不再互相盖掉画面。
- 按 GPIO5 按键唤醒只进管理页，**不会**换图、也不会改日历（设计如此）。

刷完验证（三项常规 + 五项验收）
------------------------------------------------
1. 控制页「设置」设备状态应显示：版本 R1.5.5 / 接口 2 / **帧缓冲 104 KB**（不显示「未分配」）。
2. 「设置 → 系统维护与升级 → 升级状态」应显示绿色 **「ota_x 已确认，不会被回滚」**
   （刚重启的 12 秒内可能是黄色「正在自我确认」，等一会儿刷新即可）。
3. 传一张图，屏幕应在约 15~25 秒内完成刷新。

□ V1 固件升级保留要键：上传 moink_R1.5.5_app.bin → 设备重启后版本显示 R1.5.5，
   上述 6 项回到默认，而**热点名/密码、局域网配置、轮播画面、轮播/日历设置与待办清单保持不变**。

□ V2 页面热更不重启：上传 page-R1.5.5.html → **不重启**，
   刷新浏览器页面即生效，版本显示 R1.5.5。

□ V3 自定义节奏：设置 →「休眠与唤醒」→「自动唤醒」填 **1** 分钟并保存
   → 提示应显示「每 1 分钟」；约 3 分钟后设备自己醒来开热点（此时页面掉线属正常）。
   醒来后再连上设备，「升级状态」应仍是绿色已确认（这一条就是在验 R1.5.4 的②：入睡不再触发回滚）。

□ V4 日历：设置 →「日历自动改日期」→
   ①「设备日期」显示今天的日期（开着联网时它自己校，不需要手动同步）；
   ② 点「立即显示今天」→ 约 15~25 秒后屏上是**竖版日历**；
   ③ 勾「自动改日期」、换日时刻保持 00:01 →「保存日历设置」→
      「下次改日期」显示设备自己的倒计时（形如「约 10 小时 30 分后（每天 00:01）」）；
   ④「自动校时」这行若显示「尚未自动校时」，**等 12 秒让页面补读一次**再判断
      （开机校时约在 5~6 秒完成，早于它的读数不可信）。

□ V5 局域网联网（回归项）：设置 →「局域网连接」→ 勾「启用联网」，填家里 WiFi 名/密码
   → 保存后设备信息出现「局域网 IP」；手机连同一 WiFi，用这个 IP 打开创作页能正常传图。

本版判据（R1.5.5，已在本机实机验收）
------------------------------------------------
☑ J1 断电重上电自动回日历：拔电 10 秒再插回，**插回后 45 秒内不要打开页面、不要点任何按钮**，
   屏上应在约 20~30 秒内自己回到当天日历。实机串口抓到的链路是：
   SNTP（开机 5.1 秒）→「day 20732 content unknown on panel, catching up」
   →「frame written in 236 ms」→「refresh done in 14013 ms」。
   （R1.5.3 / R1.5.4 的现场是这条链路根本不启动 —— 就是①那行判错。）
☑ J2 到点自己换日：把换日时刻等 settings 提前是**不够**的（今天已上屏时倒计时只会指向明天），
   实机验证法是把手机钟点临时调到明天再点「同步今天日期」，把设备"假提前"一天，
   随后设备空闲入睡、被 RTC 叫醒，屏上自己挂出**明天**的日期；已验到「完美自动到 10 月 7 日」。
   ※ 验完记得把手机时间改回来：设备距上次校时不满 12 小时时不会自己纠回，需要重开一次设备页补推。
☑ J3 R1.5.4 判据回归：刷完能进设置页、帧缓冲显示 104 KB、「升级状态」绿色已确认，
   空闲深睡一次后仍是绿色（没有被静默回滚）。
□ J4 未修的已知边界（如实告知，不算本版失败）：
   · 手动传图 / 传待办**会盖掉日历**，直到下一个换日时刻才回日历 —— 同一块屏只有一个主人，
     目前只能靠「立即显示今天」手动请回日历。
   · 日历上屏的「成功」指的是帧已交给显示任务；若之后显示任务本身失败，当天仍会被记为已刷。

※ 「刷了没生效」的两种现场：
   ① 新固件在 ota_1 且镜像完好，但 otadata 里它的 state = ABORTED —— 自确认窗口内被复位 / 崩溃过，
      bootloader 永久跳过它、回到 ota_0 的旧版。R1.5.4 起这件事**在页面上看得见**（升级状态药丸）。
   ② 网页里显示的还是旧页面 —— 那不是固件问题，是热更页面盖住了内置页，点「恢复内置页面」。
   otadata 的原始字节人肉解码不可靠，判断「现在到底跑哪个版本」只认页面显示的版本号。

本版主要更新（R1.5.x 累计，相对 R1.4.0）
------------------------------------------------
- ★ 掉电 / 复位 / 升级后的那次开机强制把当天日历回屏（R1.5.5，改的是唤醒原因判据）。
- ★ 控制页日历卡片：开机校时未完成时的假阴性改为「最多补读一次」，不轮询；
  长说明折叠，常驻只留「开着启用联网就不必手动同步」。
- ★ 帧缓冲按画像分配 + 分配失败不再自杀（R1.5.4）：运行期容量成为每条写入路径的唯一上限，
  收帧 / 读槽 / 日历上屏都按实际缓冲设限，800×600 只在对照档且缓冲够时被接受；
  开机用 ERROR 级日志打印 `fb / free heap / largest block`，现场诊断不必猜。
- ★ OTA 自确认提前到 frame_init 之后立刻起算、窗口 12 秒，且进入深睡前强制兜底确认（R1.5.4）；
  `/api/info` 新增 fb / heap_max / ota_run / ota_state / ota_other / ota_other_state 六个字段。
- ★ SNTP 自动校时 + 时区（R1.5.2）：日历开着且局域网拿到 IP 时，每次开机 / 距上次满 12 小时
  自动校一次，按手机推来的时区落成设备本地墙钟（tz_min 落 NVS）；没配联网时退回页面推日期。
- ★ 日历 ⇄ 相册轮播互斥由固件强制（R1.5.2）。
- ★ 日历自动改日期：竖版日历（552x768 逻辑画布旋进横屏帧，全程只有一块 106 KB 缓冲；恒为竖版，无横版开关）；
  四套样式在设备设置里选：
    · 暖纸（默认，方案 B1）= 圆角黄块（黄/白斜纹混色，无描边框）内三行黑字「2026年10月 / 5 / 星期三」+ 不画格线的周一起月格，

旧固件 / 旧页面的不兼容说明（重要）
------------------------------------------------
- R1.1.x 的固件里**没有**统一升级入口（/api/upload）。把 page-R1.5.5.html
  热更到一台还是 R1.1.x 固件的设备上再去点升级，页面会提示
  「设备固件过旧，不含统一升级入口」—— 这是预期行为，请先按方式 B 线刷到本版。
- R1.5.x 固件里同样**没有**老的 /api/ota 与 /api/web 路由，R1.1.x 的旧页面
  也无法升级本版设备。请使用本包里的页面。
- 页面与固件最好同批使用。把本页面热更到 R1.5.3 及更旧固件上：
  「日历自动改日期」照常可用，「帧缓冲」「升级状态」两项会显示「—」（旧固件不上报），
  「自动校时」在 R1.5.1 及更旧固件上会显示不含该字段，其它功能不受影响。
- 恢复内置页面按钮仍在（设置页「① 升级」下方），用于把热更的控制页清掉、
  回到固件编译进去的那一份；「恢复出厂」会连同轮播与日历设置一起清空。
